# Recipe .env format

One file per image, `images/recipes/<NAME>.env`, sourced by `images/build.sh` (shell `KEY=value`).

| Key | Meaning |
| --- | --- |
| NAME | image name, output `<NAME>.qc2` |
| RELEASE | Ubuntu release (noble) |
| VARIANT | debootstrap variant (`minbase`) |
| MIRROR | arm64 packages live on ports: `http://ports.ubuntu.com/ubuntu-ports` |
| PACKAGES | space-separated apt packages |
| SCRIPTS | space-separated files from `images/scripts/`, run in the chroot in order |
| OVERLAYS | dirs under `images/overlays/` copied over the rootfs (may be empty) |
| SIZE | disk size, e.g. `10G` |
| MINGUI | `1` = apply phenix `mingui` post-build (xfce + root autologin), `0` = headless |

Owners of other recipes (opc, historian, ...) should follow the same keys.

Extra key: `INJECT_MINIROUTER=1` also injects the arm64 `minirouter` binary. Absolute paths in SCRIPTS/OVERLAYS are used as-is.
Build: `images/build.sh <NAME>` (Mac; drives the Lima VM, serialized with flock). Output `/phenix/images/<NAME>.qc2`, GPT+ESP, root = partition 2.

bennu-arm64 (jammy): needs `images/overlays/bennu-arm64/` (gitignored, 540 MB) made by
`docker build -f images/docker/bennu-arm64.Dockerfile -t bennu:arm64 .build/bennu-src` (see the Dockerfile header for the HEAD export; two documented deviations: drop opendssdirect.py, swap vendored x86 libzmq.a), then
`docker cp <id>:/usr/local images/overlays/bennu-arm64/usr/`, then rebuild pybennu's x86 swig `_Endpoint.so` with `images/build_endpoint_so.sh` (run in bennu:arm64, /out = the swig dir in the overlay), delete `_Endpoint.pyd`.
Smoke: `docker run --rm --network host -v .build/bennu-src/data:/data -v images/bennu-smoke.sh:/smoke.sh bennu:arm64 bash /smoke.sh`.
Gotchas: vmdb scripts run under `sh -ec` (POSIX only); after experiment start, `mm namespace X clear cc filter` before `cc exec` (a leftover filter silently swallows commands); never `cc exec bennu-brash --help` (it blocks miniccc).
Kali: RELEASE=kali-rolling, MIRROR=http://http.kali.org/kali; build.sh seds the vmdb's linux-{image,headers}-amd64 to -arm64.

caldera-arm64 (noble mingui, built + verified in ww-ebo.5 via topologies/caldera-test; the app-added server node lacks arm64 machine/bios attrs so define the caldera node in the topology; phenix default config lacks `magma`, pass a `config:` adding it for the UI): `scripts/caldera.sh` installs Caldera 5.2.0 (+ activeshadow modbus/dnp3/ot/phenix plugins, magma UI built with a temporary Node 22) in `/opt/caldera` with a venv and a `caldera.service` (`server.py --insecure`, so the phenix-injected `conf/default.yml` is used). Sandcat's default agent arch is sed-patched to arm64. Firefox from the Mozilla apt repo for the app's XFCE autostart.
Use in burger's caldera board / any scenario: `image: caldera-arm64.qc2` in the phenix `caldera` app `servers:` entry (set `memory: 4096` on small hosts; the default is 8192). Linux targets get sandcat via `/etc/phenix/startup/90-sandcat-agent.sh`.

kali-purple-arm64 (kali-rolling mingui, ww-ebo.2, blue team): Kali Purple tool groups (`kali-tools-identify/-protect/-detect/-respond/-recover`), cyberchef, firefox-esr, docker.io + compose, and Malcolm v26.10.0 in `/opt/malcolm`.
Build in two steps: (1) `limactl shell phenix -- bash images/malcolm-stage.sh` runs Malcolm's own `scripts/configure --non-interactive --defaults` and `scripts/auth_setup --auth-noninteractive` against a staging copy (compose image tags rewritten to `:26.10.0-arm64`, the only arm64 tags), applies live capture and heap edits, pulls the 23 arm64 images and writes the overlay `/phenix/images/overlays-src/kali-purple` (`opt/malcolm` + 6.6 GB `opt/malcolm-images.tar.gz`); (2) `images/build.sh kali-purple-arm64` (SIZE=80G, ~13 GB qc2).
The chroot cannot run docker, so: `malcolm-firstboot.service` does `docker load` once (about 8 min on first boot, then deletes the tarball and touches `/opt/malcolm/.images-loaded`) and `malcolm.service` runs `docker compose --profile malcolm up -d` on every boot (Malcolm containers have `restart: "no"`). Allow about 5-10 more minutes after that for OpenSearch/Dashboards/NetBox to go healthy.
Capture NIC = the VM's SECOND interface, guest name `eth1` (`PCAP_IFACE=eth1`). `capture-nic.service` flushes its IP (phenix requires an address on every interface; give it a placeholder such as 192.0.2.250/24), sets promisc, turns off offloads; NetworkManager is told to leave eth1 alone. Live capture is ON: ZEEK_LIVE_CAPTURE, SURICATA_LIVE_CAPTURE, ARKIME_LIVE_CAPTURE and PCAP_ENABLE_NETSNIFF (netsniff-ng also writes rotating pcaps under /opt/malcolm/pcap for the offline Zeek/Suricata/Arkime processors). If the capture iface is not eth1 (extra mgmt NIC first), edit `PCAP_IFACE` in `/opt/malcolm/config/pcap-capture.env`.
Detection add-ons (ww-ebo.10): `suricata/rules/ics-mitm.rules` (from `images/malcolm-suricata/`, picked up by suricata-live via Malcolm's custom-rules dir) alerts on Modbus writes (FC 5/6/15/16/22/23) to the RTUs from anyone but the OPC gateway 10.1.2.50 (sid 9100001), diagnostic/encapsulated/report-id/exception-status/odd function codes (9100010-16) and RTU exception responses (9100020). Suricata cannot match ARP at all (`protocol "arp" cannot be used in a signature`), so ARP spoofing stays with `arp-spoof.zeek`. Offline test: `images/malcolm-suricata/mkmodbus.py` writes `modbus-test.pcap`. Arkime: `tcpSaveTimeout` is lowered 720 s -> 90 s (override with `ARKIME_TCP_SAVE_TIMEOUT=<s>` in `config/arkime-live.env`) by a patched `arkime/live_capture.sh` bind-mounted over the image's (no env knob exists; capture takes `-o tcpSaveTimeout=`), so a never-closing Modbus connection shows up in Arkime ~90 s in, not 12 min; cost: more partial session docs per long flow. Save query evidence with `scripts/blue-evidence.sh`.
Resources: OpenSearch heap 3g (default 10g), Logstash 2g (1g OOMs the zeek pipeline), PUID/PGID 1000; the offline `suricata`, `strelka-backend`, `netbox`, `postgres` and `keycloak` services are moved to an unused `extras` compose profile and NETBOX_MODE=disabled (about 6 GB saved; live Suricata/Zeek/Arkime and the web UI are unaffected; no NetBox UI or enrichment). With everything on, the stack needs more than 15 GB and a 16 GiB VM thrashes. `opensearch` publishes 127.0.0.1:9200 and `arkime-live` maps `opensearch` to 127.0.0.1 because the live containers use host networking and could not otherwise reach OpenSearch. `vm.max_map_count=262144` is set via sysctl.d.
**Malcolm web login: https://<blue-vm-mgmt-ip>/ (self-signed cert), user `admin`, password `MalcolmBlue1!` (basic auth; Arkime viewer uses the same). Console: root / toor.** Change it with `/opt/malcolm/scripts/auth_setup` or by overriding `MALCOLM_PW` in `images/malcolm-stage.sh`.
Phenix/cc gotcha: `cc send` does NOT overwrite a same-named file already delivered to the guest; use a new file name per iteration.

ARCH=amd64 recipes (ww-lwv.1; `ubuntu-amd64` is the proof): add `ARCH=amd64` and `MIRROR=http://archive.ubuntu.com/ubuntu`; default is arm64 so existing recipes are unchanged. build.sh installs `qemu-user-binfmt` in the Lima VM if `/proc/sys/fs/binfmt_misc/qemu-x86_64` is missing (F flag, so it works inside the phenix container's chroots; no container restart), seds `arch: amd64` into the vmdb's debootstrap step (vmdb2 sets state.arch -> grub-pc/i386-pc), skips uefi_patch.py (msdos + grub bios, root = partition 1) and injects an amd64 `miniccc` cross-built from ~/git/minimega (`/phenix/amd64/miniccc`; inject-miniexe needs the file named miniccc). Build is slow under qemu-user (~12 min for a minimal image).
Boot (topologies/ign-amd64): `hardware.cpu: max`, `advanced.qemu: /usr/bin/qemu-system-x86_64` (ABSOLUTE; a bare name resolves under /phenix/images), `qemu-append: ""` (drops `-vga qxl`), and NO `advanced.machine` (validated against the default aarch64 qemu: `pc` is rejected, plan 1.1 ordering trap). TCG, miniccc checks in about 1-2 min.
Verified (blue-test, 16 GiB/6 vCPU): first boot loads images (~8 min), all 22 containers healthy ~15 min after, `https://localhost/` 401 without / 200 with login, zeek-live, suricata-live, arkime-live `capture` and netsniff-ng all bound to eth1 (`ss -0apn`), 300 synthetic DNS frames sent out eth1 appeared as 300 Arkime sessions in OpenSearch and 308 rows in live dns.log. Re-verified at 20 GiB / 8 vCPU with Logstash 2g (ww-ebo.7, rebuilt image): cc up 32 s after start, docker load done ~7 min, 22/22 healthy at +10m46s (18:23:00 -> 18:33:46), UI 200; replaying docs/mitm-capture.pcap and 60 synthetic DNS frames out eth1 put Zeek modbus 168 / modbus_detailed 86 / conn 65 / dns 60 and 64 Arkime sessions into `arkime_sessions3-*` (query https://127.0.0.1:9200 with `/opt/malcolm/.opensearch.primary.curlrc`, `-k`), no Logstash OOM; steady state `free -g`: 16 used, 3 available, no swap (Logstash RSS 2.6 GB, OpenSearch 4 GB). 20 GiB is the floor; the mitm topology gives blue 24 GiB (ww-ebo.10) for Firefox headroom. Earlier 16 GiB figures: Memory is tight: about 14 GB used after boot, 15.4 GB with Firefox open; prefer 20 GiB. Firefox shows a self-signed cert warning once (UNKNOWN_ISSUER, the cert is not a CA so the Certificates.Install policy does not trust it): Advanced, Proceed. Screenshot: docs/shots/malcolm.png. Not done: NetBox, Keycloak, Strelka scanning, offline Suricata (parked in the `extras` profile).

ignition-amd64 / ignition-arm64 (ww-lwv.2, Ignition 8.1.55 gateway for SOAP; status: IMAGES BUILD, gwbk restore NOT yet verified, see below):
- Packaging evidence (2026-11-08): the downloads page (inductiveautomation.com/downloads) offers only Linux x86_64 `.run` installers (current 8.3.10: `releases.inductiveautomation.com/release/8.3.10/20261006-1109/ignition-8.3.10-linux-64-installer.run`); no aarch64 zip/.run is published there. The official Docker image `inductiveautomation/ignition` (Docker Hub) ships amd64, arm64 and arm for 8.1.x/8.3.x, so both recipes use IA's per-arch image tree (8.1.55; the SOAP .gwbk is an 8.1 backup, sqlite `db_backup_sqlite.idb` + Vision project `soap_hil`).
- `images/ignition-stage.sh <amd64|arm64>` pulls the image in the Lima VM and tars `/usr/local/bin/ignition` into `/phenix/images/overlays-src/ignition-<arch>/opt/ignition-tree.tar` (~2 GB; a tar because vmdb2 copy-dir hangs on the tree's `logs/wrapper.log -> /dev/stdout` symlink). `scripts/ignition.sh` unpacks it, sets memory 512M-2G, adds `gwcmd` (waits for RUNNING, then `gwcmd.sh`; SOAP calls `gwcmd`) and `ignition.service` (root, trial mode, no licence). arm64: `lib/runtime/jre-nix` symlinked to `jre-aarch64`.
- Build: `images/build.sh ignition-arm64` (~4 min, 3 GB qc2), `images/build.sh ignition-amd64` (~13 min under qemu-user). SIZE=12G, boot with >= 8 GiB.
- Trial mode: no licence key needed; after the 2-hour trial the gateway stops serving clients/designer until reset from the Gateway web UI (Config > System > Licensing > Reset Trial); it keeps running.
- BLOCKER, first start is uncommissioned: 8.1 comes up with `{"state":"RUNNING","details":"COMMISSIONING"}` (wizard: EULA, ports) and `gwcmd --restore` is silently not applied then (it stages `data/__restore_*.gwbk`, which nothing consumes; restarting or running the Upgrader does not help). SOAP's injected command runs ~100 s after boot, before anyone commissions. Headless commissioning = POST /post-step {license/eula accept:true}, {connections http 8088 https 8043 gan 8060}, {finished}; that means accepting IA's EULA, which the permission system would not let an agent do. `scripts/ignition.sh` implements it behind an opt-in marker: run `IGNITION_ACCEPT_EULA=1 images/ignition-stage.sh <arch>` (you accept the EULA), rebuild, then boot-test with `topologies/ign-test/ign-<arch>-topology.yaml` (gwbk copied to `/phenix/ignition-test/`).
- Operating note: cc responses of a long `cc exec` only arrive when the command ends; use short commands.

mqtt-arm64 / mqtt-amd64 (ww-ko6): Mosquitto broker from the distro package, 4G, headless. See `docs/mqtt-broker.md` (lab-default anonymous access, how to inject passwd/acl/certs). `gen_topology.py --mqtt` adds it at 10.1.1.60 on the ICS VLAN.

bennu-ferrofire-arm64 (ww-1df.9, ww-1df.28): `scripts/ics-net.sh` adds `/etc/sysctl.d/90-ics-udp.conf` (wmem/rmem default+max 4/8 MiB, so an 8112-tag RADIO cycle is not dropped with EAGAIN) and `/etc/phenix/startup/5_ics-net-start.sh` (runs after phenix's `3_interfaces-start.sh`, which flushes and re-adds addresses): `ip route replace 224.0.0.0/4 dev <iface on 172.16.*, else first IPv4 iface>`, so a VM with no default route no longer fails multicast sends with ENETUNREACH. The soap-arm64 RTUs use this image too. Rebuild with ferrofire's `./build-linux.sh` -> copy `dist/ferrofire` to `images/overlays/ferrofire/usr/local/bin/` -> `images/build.sh bennu-ferrofire-arm64`.
Breaker-write check: `topologies/soap-arm64/dnp3-breaker-check.sh` (DNP3 master `tools/dnp3-master`, stepfunc `dnp3` crate, on VM `dnp3-master` at 10.117.4.110; the fd-server outstations listen only on their EXP address, outstation link address 10, binary index = tag order in the RTU's config.xml, rtu-3 branch-1_243-244.active = 16).
